# Marginalia Books: a full-stack book store

A complete online bookstore: browse and search books, keep a cart, check out, and manage everything from an admin dashboard. Built with **React (Vite)**, **Node.js + Express** and **MongoDB (Mongoose)**.

* Visitors can browse the catalogue; they must log in to place an order.
* Admins manage books, stock, orders and users from a protected dashboard.
* Prices and stock are always validated on the server. There is **no real payment gateway**: orders are "pay on delivery", and the UI says so clearly.

## Prerequisites

* **Node.js 18 or newer** (`node -v`) and npm.
* **A MongoDB database.** `npm install` cannot create or start a database for you. Use a local MongoDB, Docker, or a free MongoDB Atlas cluster (see [MongoDB setup](#mongodb-setup)).

## Quick start

```bash
npm install        # installs root + server + client dependencies and creates server/.env
# make sure MongoDB is running (see below), then:
npm run seed       # sample books + your first admin account
npm run dev        # starts the API and the web app together
```

* Web app: <http://localhost:5173>
* API: <http://localhost:5000> (health check: <http://localhost:5000/api/health>)

`npm install` runs a `postinstall` step that installs `server/` and `client/` and creates `server/.env` from `server/.env.example` with a freshly generated random `JWT_SECRET`. Existing `.env` files are never overwritten. You can re-run this step with `npm run setup`.

Before running `npm run seed`, open `server/.env` and set the `ADMIN_*` values (see [Seed data](#seed-data-and-the-first-admin)).

## Environment variables

All variables live in `server/.env` (copy of `server/.env.example`). Never commit the real file; `.gitignore` already excludes it.

| Variable | Default | Purpose |
| --- | --- | --- |
| `PORT` | `5000` | API port. The Vite dev proxy reads this value too. |
| `MONGODB_URI` | `mongodb://127.0.0.1:27017/book_store` | Local MongoDB or an Atlas `mongodb+srv://` string. |
| `JWT_SECRET` | generated by `npm install` | Secret used to sign login tokens. Use a long random value. The server refuses to start without it, and in production refuses the placeholder. |
| `JWT_EXPIRES_IN` | `7d` | Token lifetime. |
| `CLIENT_URL` | `http://localhost:5173` | Allowed browser origin(s) for CORS (comma separated). Only matters when the front-end is hosted separately. |
| `ADMIN_NAME`, `ADMIN_EMAIL`, `ADMIN_PASSWORD` | placeholders | Used **only** by `npm run seed` to create the first admin. |

Create the file manually if you prefer:

```bash
cp server/.env.example server/.env
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"   # paste the output as JWT_SECRET
```

Optional (front-end build time): `VITE_API_URL` sets the API base URL when the front-end is hosted on a different domain, for example `https://api.example.com/api`.

## MongoDB setup

Pick one:

**A) Docker (quickest)**

```bash
docker run -d --name bookstore-mongo -p 27017:27017 -v bookstore-data:/data/db mongo:7
```

Keep the default `MONGODB_URI=mongodb://127.0.0.1:27017/book_store`.

**B) Local install**: install MongoDB Community Edition from <https://www.mongodb.com/docs/manual/installation/>, start the `mongod` service, and keep the default URI.

**C) MongoDB Atlas (free cloud database)**

1. Create a free cluster at <https://www.mongodb.com/atlas>.
2. Create a database user (username and password).
3. Under *Network Access*, allow your IP address (or `0.0.0.0/0` for testing only).
4. Click *Connect → Drivers* and copy the connection string.
5. Put it in `server/.env`, adding the database name before the `?`:

```env
MONGODB_URI=mongodb+srv://<user>:<password>@<cluster>.mongodb.net/book_store?retryWrites=true&w=majority
```

If the database is unreachable the API still starts, `/api/health` reports `database: "disconnected"`, data routes answer `503` with a clear message, and the server retries every 5 seconds.

## Seed data and the first admin

Public registration **never** creates admins. The first admin is created by a seed script:

1. In `server/.env` set a real admin account:

   ```env
   ADMIN_NAME=Your Name
   ADMIN_EMAIL=you@example.com
   ADMIN_PASSWORD=choose-a-strong-password   # at least 8 characters
   ```

2. Run:

   ```bash
   npm run seed
   ```

What it does:

* Adds 20 sample books (real titles, authors, categories, prices, descriptions and Open Library cover URLs), skipping any book whose title and author already exist.
* Creates the admin with a bcrypt-hashed password, unless that email already exists. An existing account is **never** modified, so passwords are never overwritten.
* If `ADMIN_EMAIL` / `ADMIN_PASSWORD` are missing (or still the placeholder) and you run it in a terminal, it asks for them interactively (the password is hidden). Without a terminal it skips the admin and tells you why.
* Safe to run repeatedly. Options: `npm run seed -- --books-only` and `npm run seed -- --admin-only`.

After the first admin exists you can promote other users from **Admin → Users**. You may remove the `ADMIN_PASSWORD` line from `.env` afterwards.

## Running the project

```bash
npm run dev
```

starts both processes and prints clear prefixed logs (`[api]`, `[web]`):

* Express API on `http://localhost:5000` (restarts on file changes via `node --watch`).
* Vite on `http://localhost:5173`, proxying `/api` to Express, so there are **no CORS problems in development**. If you change `PORT` in `server/.env`, the proxy follows automatically.

Other root commands: `npm run seed`, `npm run build`, `npm start` (API, and the built front-end if present), `npm run smoke` (API test, see [Testing](#testing)), `npm run setup`.

## Workflows

**Visitor / user**

1. Browse the home page, then **Books**: search by title or author, filter by category, sort by newest or price.
2. Open a book for its description, price, cover and stock; add it to the cart.
3. In the **cart** change quantities (limited by stock), remove items, see subtotal and total. The cart is saved in the browser per account (plus a guest cart that is merged into your account when you log in).
4. **Checkout** needs an account (register or log in, then you return to checkout). Enter delivery details and place the order. The server recomputes prices from the database, checks stock, reduces it, and saves the order.
5. See the confirmation page, then **My orders** for the history.

**Admin** (log in with the seeded account; you land on `/admin`)

* **Dashboard**: total books, users, orders and sales (all queried from MongoDB; cancelled orders are excluded from sales), stock alerts, recent orders.
* **Books**: search, add, edit, delete (with a confirmation dialog), and edit stock inline.
* **Orders**: filter by status, open details, change status. Cancelling returns the books to stock exactly once.
* **Users**: list, search, change role, delete (you cannot change or delete yourself).

## Authentication and security

* **Flow**: `POST /api/auth/login` (or `register`) returns `{ token, user }`. The front-end stores the JWT in `localStorage` and sends it as `Authorization: Bearer <token>`. On page load the token is verified with `GET /api/auth/me`; expired or invalid tokens log the user out automatically.
* **Why this storage?** A Bearer token keeps the front-end and API independent (works with the Vite proxy, separate hosting, and mobile clients) and needs no CSRF protection. The trade-off is that `localStorage` is readable by injected scripts (XSS). React escapes rendered content by default and the app never uses `dangerouslySetInnerHTML`, and tokens expire (`JWT_EXPIRES_IN`). If you need stricter protection, switch to an `httpOnly`, `Secure`, `SameSite` cookie plus CSRF protection.
* **Passwords** are hashed with `bcryptjs` (cost 12), are never selected by default, and are stripped from JSON output.
* **Roles are enforced on the server.** The role is read from the database on every request, never from the token or the client. `/api/users`, `/api/admin`, book writes and order administration all require an admin. Registration ignores any `role` field.
* **Prices are never trusted**: checkout accepts only book ids and quantities.
* **Stock is safe under concurrency**: each book is decremented with an atomic conditional update (`stock >= quantity`), and anything already reserved is restored if a later step fails.
* **Other protections**: input validation on every write, regex-escaped search, JSON body size limit, per-IP rate limit on login/register, consistent error responses, secrets only in environment variables.

## API reference

All responses are JSON. Success: `{ "success": true, ... }`. Errors: `{ "success": false, "message": "...", "errors": { field: message } }` with a meaningful status code (400 validation, 401 not logged in, 403 not allowed, 404 not found, 409 conflict, 503 database down).

| Method | Endpoint | Access | Description |
| --- | --- | --- | --- |
| GET | `/api/health` | public | Server and database status |
| POST | `/api/auth/register` | public | Create a user account |
| POST | `/api/auth/login` | public | Log in, returns token and user |
| GET | `/api/auth/me` | user | Current user |
| GET | `/api/books` | public | List books. Query: `search`, `category`, `sort` (`newest`, `price_asc`, `price_desc`, `title`), `page`, `limit` (max 100), `ids` (comma list) |
| GET | `/api/books/categories` | public | All categories |
| GET | `/api/books/:id` | public | One book |
| POST | `/api/books` | admin | Create a book |
| PUT | `/api/books/:id` | admin | Update a book |
| DELETE | `/api/books/:id` | admin | Delete a book |
| POST | `/api/orders` | user | Place an order: `{ items: [{ bookId, quantity }], shippingAddress: { fullName, phone, address, city, postalCode } }` |
| GET | `/api/orders/mine` | user | Your order history |
| GET | `/api/orders/:id` | owner or admin | One order |
| GET | `/api/orders` | admin | All orders. Query: `status`, `page`, `limit` |
| PATCH | `/api/orders/:id/status` | admin | Set status (`placed`, `processing`, `shipped`, `delivered`, `cancelled`) |
| GET | `/api/users` | admin | List users. Query: `search`, `page`, `limit` |
| GET | `/api/users/:id` | admin | One user and their order count |
| PATCH | `/api/users/:id/role` | admin | Set role `user` or `admin` |
| DELETE | `/api/users/:id` | admin | Delete a user |
| GET | `/api/admin/stats` | admin | Dashboard statistics and recent orders |

Book fields: `title`, `author`, `description`, `price` (>= 0), `category`, `coverUrl` (optional http(s) URL), `stock` (whole number >= 0), `isbn` (optional, 10 or 13 digits), `createdAt`.

## Testing

With MongoDB running and the database seeded (the admin from `ADMIN_EMAIL` / `ADMIN_PASSWORD` in `server/.env` must exist), start the API and run the smoke test in a second terminal:

```bash
npm run dev      # terminal 1
npm run smoke    # terminal 2
```

It exercises auth, validation, permissions, book CRUD, checkout, stock protection (including two simultaneous orders for the last copies), order status changes and user management, and creates and cleans up its own temporary data. It prints `ok` / `FAIL` per check and exits non-zero on failure.

## Production build

```bash
npm run build                      # builds client/dist
NODE_ENV=production npm start      # Express serves the API and the built app on one port
```

On Windows PowerShell use `$env:NODE_ENV="production"; npm start`. In production set a strong `JWT_SECRET`, your Atlas `MONGODB_URI`, and `NODE_ENV=production`. With this single-server setup, no CORS configuration is needed.

## Deployment guidance

* **Database**: use MongoDB Atlas. Create a dedicated database user, restrict network access to your host's IPs where possible, and use the `mongodb+srv://` string as `MONGODB_URI`.
* **Option 1, one service** (simplest): deploy the whole repo to a Node host (Render, Railway, Fly.io, a VPS). Build command `npm install && npm run build`, start command `npm start`, and set `NODE_ENV=production`, `MONGODB_URI`, `JWT_SECRET`. On Railway, add `MONGODB_URI` as a service environment variable with the MongoDB Atlas connection string (including the `book_store` database name); production does not fall back to local MongoDB. Run `npm run seed` once (from your machine pointing at Atlas, or from the host's shell) to create the admin.
* **Option 2, separate hosts**: deploy `server/` as a Node service (start `npm start`, set `CLIENT_URL` to your front-end's exact origin) and `client/` to a static host (Netlify, Vercel, Cloudflare Pages) with build `npm run build`, output `dist`, and `VITE_API_URL=https://<your-api-host>/api`. Add a rewrite of all paths to `/index.html` so React Router deep links work.
* Always serve over HTTPS and keep `JWT_SECRET` out of the repository.

## Arabic and RTL later

The CSS uses logical properties (`margin-inline`, `inset-inline-start`, ...), locale and currency are centralised in `client/src/utils/format.js`, and the HTML root carries `lang`/`dir`. To add Arabic: move the UI strings into a translation file (for example with `react-i18next`), set `document.documentElement.lang`/`dir` from the chosen language in `main.jsx`, and change `LOCALE` and `CURRENCY`.

## Troubleshooting

* **"Cannot reach the server" in the browser**: the API is not running or crashed; check the `[api]` lines in the terminal.
* **`/api/health` shows `database: disconnected`**: MongoDB is not running or `MONGODB_URI` is wrong (for Atlas, check the password, the database user, and Network Access).
* **`Port 5000 is already in use`**: stop the other process or change `PORT` in `server/.env`. On macOS, AirPlay Receiver can occupy port 5000; use `PORT=5001`.
* **`JWT_SECRET is missing`**: run `npm run setup` or add it to `server/.env`.
* **Covers show a text cover instead of an image**: the cover URL is missing or unreachable. This is the intended fallback.
* **Seed skipped the admin**: set real `ADMIN_EMAIL` and `ADMIN_PASSWORD` values in `server/.env` (the placeholder password is rejected).
